# Motion Artwork — 測試與部署

單機、純前端。三軸加速度驅動:靜止=馬賽克畫面+麥克風現場音;移動=清晰影片+橫向殘影+日常音檔。

## 檔案結構
```
index.html      單頁,開始按鈕
main.js         組裝、主迴圈、除錯層
motion.js       運動偵測 + 狀態機
audio.js        麥克風 ↔ 音檔 crossfade
visual.js       WebGL 殘影 + 馬賽克
config.js       所有可調參數
shaders/        feedback.glsl(殘影)、pixelate.glsl(馬賽克)
assets/         video_01~03.mp4 + audio_01~03.mp3(你放素材)
```

## 放素材
見 assets/README.txt。成對命名,改 config.js 的 sceneCount 增減。

## 本機測試(重要)
不能直接雙擊開 index.html(shader 用 fetch 載入,file:// 會被 CORS 擋)。
必須用 local server:
```
cd motion-artwork
npx serve          # 或 python3 -m http.server
```
但本機是 http,Android Chrome 需要 HTTPS 才給麥克風+感測器。
所以真機測試最簡單的路徑是直接部署(見下)。

## 部署(拿免費 HTTPS)
把整個資料夾拖到 Netlify Drop(app.netlify.com/drop),或推到
GitHub 用 Pages,或 Vercel。得到 https 網址後用 Android Chrome 開。

## 現場校參數
- 開始後,點右上角 ⚙ 圓鈕(或電腦按 D 鍵)切換除錯面板,直接拉滑桿即時調整
- 面板左上會即時顯示:state(狀態)、motion(運動量)、tiltX(左右傾斜)、
  scene(當前第幾支)、trailMix(殘影量)、mosaic(馬賽克格子大小)
- 調到滿意後,把數值抄回 config.js 才會永久生效(滑桿只在當次有效,重整就還原)

## 各參數詳細說明

以下依面板由上到下順序。每項說明「控制什麼／調大會怎樣／調小會怎樣／建議校法」。

### 運動偵測

**moveThreshold(運動判定閾值)**
判斷「有沒有在動」的門檻。感測到的運動量超過這個值 → 進入 MOVING(清晰+殘影+日常音);低於則往 STILL(馬賽克+現場音)靠。
- 調大:要更用力晃動才會觸發清晰,系統較遲鈍、較不易誤判
- 調小:輕微移動就觸發,系統敏感,但手抖、走動可能誤判為移動
- 建議:先把手機拿穩不動,看面板 motion 讀數的雜訊落在多少(通常 0.1~0.3),把閾值設在「雜訊之上一點」。這是最該優先校的參數。

**motionSmoothing(運動量平滑度)**
對運動量做低通濾波的強度,決定讀數反應快慢。
- 調大(接近 1):反應快、靈敏,但抖動雜訊也跟著進來
- 調小(接近 0):讀數平滑穩定,但反應變慢、較鈍
- 建議:多數情況 0.15~0.3 夠用。若覺得狀態切換太神經質,調小一點。

### 狀態機節奏(作品的「脾氣」)

**stillDelay(靜止判定延遲，毫秒)**
運動量低於閾值後,要持續多久才判定為 STILL(畫面才開始糊、聲音才切回現場)。
- 調大:停下後畫面還會清晰一陣子才糊掉,系統「黏」、有餘裕
- 調小:一停就馬上糊掉、馬上切現場音,反應直接但可能太神經質
- 建議:800~1500ms 之間試。太短會在清晰/馬賽克間抖動。

**minMovingTime(最短移動停留時間，毫秒)**
進入 MOVING 後,至少維持這麼久才允許轉回 STILL。防止觀眾動一下就把影片佇列快速掃空、每支影片還沒看清就被換掉。
- 調大:每支影片被保證播放較久,節奏沉穩,但「停下」的反應會延遲
- 調小:反應即時,但觀眾亂動時影片會快速閃過、佇列快速消耗
- 建議:2000~4000ms。這個值決定觀眾能不能「看完一段」再換。

### 視覺:馬賽克(靜止時的模糊)

**mosaicMax(馬賽克最大格子，像素)**
STILL 時馬賽克的最粗程度,格子越大畫面越糊、越難辨識。
- 調大:靜止時糊得更徹底,「拒絕辨識」更強烈,聲畫背反更尖銳
- 調小:靜止時只是輕微模糊,仍能看出影片內容
- 建議:這件作品要的是「靜止=真實的聲音+崩解的影像」,建議偏大(40~60),讓馬賽克夠重。實際看你的影片再定。

**mosaicEase(馬賽克漸變速率)**
馬賽克從清晰糊化、或從糊化變清晰的快慢。
- 調大:糊化/變清晰很快,轉換乾脆
- 調小:糊化/變清晰緩慢,有「逐漸溶解」的餘韻
- 建議:0.02~0.06。這個值要和 trailEase 一起調,讓靜止時「殘影凝固→馬賽克糊上來」看起來像一氣呵成,而非兩個各自為政的動作。

### 視覺:殘影(移動時的拖影)

**trailAmount(殘影強度)**
移動時殘影拖尾的最大濃度(上一幀保留比例的上限)。
- 調大(接近 0.98):殘影拖得又長又濃,動態強烈但可能糊成一團
- 調小:殘影短、克制,影片內容較清楚
- 建議:0.7~0.9。若你的影片本身動態劇烈(快剪、鏡頭快速移動),要調得比想像中克制,否則會糊成一團看不出所以然。

**trailShiftMax(殘影最大橫向偏移，像素)**
左右傾斜手機時,殘影往傾斜方向橫向拉出的最大幅度。這是「左右倒→殘影橫移」的表現力來源。
- 調大:輕微左右傾就拉出明顯橫向殘影,效果誇張
- 調小:橫移含蓄,殘影主要是原地拖尾
- 建議:15~40。想強調「甩動」的身體感就調大。

**trailEase(殘影漸變速率)**
殘影量隨運動變化的平滑速度。
- 調大:殘影量緊跟動作,反應即時
- 調小:殘影量變化平滑,動作停止後殘影慢慢收斂(更有餘韻)
- 建議:0.1~0.2。與 mosaicEase 搭配決定靜止過渡順不順。

### 聲音

**audioFade(聲音淡入淡出速率)**
麥克風現場音 ↔ 日常音檔 之間 crossfade 的速度。
- 調大:切換快、乾脆,但可能有突兀感
- 調小:切換緩慢、綿密,兩種聲音有一段交疊
- 建議:0.02~0.05。想要「現場音緩緩被日常淹沒」的感覺就調小。

**micGainMax(麥克風現場音音量)**
靜止時麥克風收到的現場環境音的音量上限。
- 調大:現場音更明顯
- 調小:現場音更輕
- 建議:這是展場現場最需要校的聲音參數。展場環境音的實際響度無法預期(可能很安靜或很吵),而日常音檔是固定響度的,兩者的主觀音量落差要靠這個滑桿在現場校平衡。

**fileGainMax(日常音檔音量)**
移動時播放的日常音檔的音量上限。
- 調大/調小:對應日常聲音相對現場音的大小
- 建議:先固定為 1.0,主要靠 micGainMax 去對齊現場音的響度。

## 已知需真機驗證的點
1. 效能:1080p 影片 + 兩 pass + feedback,中低階機可能掉幀。
   先用 720p 素材測;若卡,可在 visual.js 的 resize() 裡把 dpr 上限從 2 再調低。
2. 靜止過渡:殘影凝固與馬賽克糊化是兩段,需調 mosaicEase 與 trailEase 配順。
3. 現場音量:展場環境音響度不可預期,用 micGainMax 現場校平衡。
4. 感測器手勢:部分新版 Android Chrome 要求手勢後才給感測器,已綁在開始按鈕。
